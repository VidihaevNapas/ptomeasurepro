# PTO Measure Pro v1.0.1 — аддон AutoCAD 2025 (.NET 8)

Плагин для замера трубопроводов, воздуховодов, кабельной продукции и штучных
изделий по чертежу. Журнал ведётся автоматически по фактической геометрии,
результат выгружается в Excel-спецификацию.

## Ключевой принцип: журнал выводится из чертежа

Журнал не заполняется руками. Источник истины — слои вида
«материал + участок». Плагин сканирует чертёж, разбирает имена слоёв обратно
в пары «материал + участок», обмеряет их за один проход и приводит журнал
в соответствие: создаёт недостающие записи, обновляет существующие, удаляет
те, чьи слои опустели.

Поэтому кнопки «Записать» нет, а переключателя инструментов нет тем более —
тип замера определяется классом материала.

## Сборка

```bash
dotnet build "CadMeasure.sln" -c Release -p:Platform=x64
```

Путь установки AutoCAD задан в `CadMeasurePlugin.csproj` свойством `AcadInstallDir`
(по умолчанию `C:\Program Files\Autodesk\AutoCAD 2025\`). Если AutoCAD стоит
в другом месте:

```bash
dotnet build "CadMeasure.sln" -c Release -p:Platform=x64 -p:AcadInstallDir="D:\Autodesk\AutoCAD 2025\"
```

Результат: `src\CadMeasurePlugin\bin\x64\Release\net8.0-windows\CadMeasurePlugin.dll`
плюс `CadMeasureDomain.dll`, ClosedXML с зависимостями и `materials.json`.
Сборки самого AutoCAD в выходную папку не копируются (`Private=false`) — это
обязательное условие, иначе AutoCAD загрузит второй экземпляр типов.

## Установка

Пакет для распространения собирается целью `Bundle`:

```bash
dotnet build "src\CadMeasurePlugin\CadMeasurePlugin.csproj" -c Release -p:Platform=x64 -t:Bundle
```

Результат — папка `dist\PTOMeasurePro.bundle`. Установка сводится к одной
операции: скопировать её в `%PROGRAMDATA%\Autodesk\ApplicationPlugins`.
Реестр Windows не правится, `NETLOAD` не нужен — AutoCAD сам сканирует
`ApplicationPlugins` при запуске и читает `PackageContents.xml`.

Скрипты в `deploy` — эталон этих операций для инсталлятора (MSI, Inno Setup,
WiX) и рабочий способ поставить плагин руками:

```bash
powershell -ExecutionPolicy Bypass -File deploy\install.ps1
powershell -ExecutionPolicy Bypass -File deploy\uninstall.ps1
```

`install.ps1` годится и для обновления: старая папка удаляется целиком, на её
место встаёт новая. Данные пользователя (`%APPDATA%\PTOMeasurePro` — реестр
материалов и настройки палитры) лежат вне bundle и при обновлении не
затрагиваются. `uninstall.ps1` их тоже сохраняет; для полной очистки —
ключ `-RemoveUserData`.

## Запуск

Штатный путь — установка пакета (см. раздел «Установка»): AutoCAD загружает
плагин сам при запуске. Для разработки можно по старинке: `NETLOAD` →
`CadMeasurePlugin.dll`.

Палитра открывается командой `CMP` (или `ЗАМЕРЫ`).

Команды:

| Команда | Назначение |
|---|---|
| `CMP`, `ЗАМЕРЫ` | открыть палитру замеров |
| `CMPDRAW` | режим рисования замерных полилиний (обычно запускается кнопкой «Начать замер») |
| `CMPTABLE` | вставить ведомость в чертёж |
| `CMPRELOAD` | перечитать `materials.json` |
| `CMPHELP` | справка по командам |

## Реестр материалов

При первом запуске файл создаётся с готовой номенклатурой — **558 позиций**:

| Класс | Позиций | Что входит |
|---|---|---|
| `Pipe` | 120 | сталь электросварная и ВГП, медь, PP-R PN10/PN20, PE-X, металлопластик, ПНД ПЭ100, канализация ПВХ/ПП/SML |
| `Duct` | 62 | 34 прямоугольных сечения, 22 круглых спирально-навивных, гибкие |
| `Cable` | 117 | ВВГнг(А)-LS, ВВГнг(А)-FRLS, ПвВГнг(А)-LS, NYM, КВВГнг(А)-LS, КПСнг(А)-FRLS |
| `Piece` | 259 | фасонные изделия трубопроводов, запорная арматура, фланцы и заглушки, фасонные изделия вентиляции, оборудование |

Толщина листа воздуховода назначается по большей стороне, как в СП 60.13330.

Поля позиции: `Class` (`Pipe` / `Duct` / `Cable` / `Piece`), `Name`, `Unit`
и nullable характеристики `DiameterMm`, `WallThicknessMm`, `WidthMm`,
`HeightMm`, `SheetThicknessMm`, `NominalDiameterMm`, `CoreCount`,
`CrossSectionMm2`, `PieceKind`. Поиск и навигация идут по `Name`.

### Дробные размеры

Диаметр трубы, толщина стенки и толщина листа — `double?`: ⌀21,3x2,8 и
сталь 0,7 мм задаются как есть. Стороны прямоугольного воздуховода и
условный проход Dn остались целыми.

Форматы намеренно разные:

| Где | Формат | Пример |
|---|---|---|
| Ввод в UI | запятая или точка | `3,5` или `3.5` |
| Показ в палитре и Excel | локаль пользователя | `⌀21,3x2,8` |
| Хранение в JSON | инвариантно (требование формата) | `"WallThicknessMm": 3.5` |
| Имя слоя | инвариантно (запятая в именах слоёв запрещена) | `PIPE_D21.3x2.8` |

При чтении `materials.json` принимаются и число `3.5`, и строки `"3.5"` и
`"3,5"` — файл правят руками в русской раскладке, и запятая туда попадает
постоянно.

### Круглые воздуховоды

Задаются диаметром вместо пары «ширина+высота». Характеристика — `⌀200, 0,7 мм`,
слой — `DUCT_D200_t0.7`. В окне добавления сечение переключается радиокнопками.

### Пополнение реестра

В окне выбора материала три кнопки: «Добавить материал» (позиция с нуля),
«Копировать выбранный» и «Удалить материал». Класс материала берётся от
активного инструмента.

**Копирование** переносит все поля, включая наименование, — правится копия
на месте. Уникальность проверяется при сохранении, поэтому сохранить копию,
не изменив наименование, не выйдет.

Числовые характеристики необязательны. Наименование обязательно и должно быть
уникальным: по нему идут поиск, журнал и слои, поэтому дубликат отклоняется
с сообщением. После сохранения позиция сразу пишется в `materials.json`,
появляется в списке и получает свой слой в чертеже. Если записать файл не
удалось, материал не попадает и в список — реестр в памяти и на диске
не расходятся.

### Удаление материала

Каскад в строгом порядке: **полилинии → записи журнала → позиция реестра → слой**.
Диалог подтверждения показывает реальные последствия — сколько объектов на
слое и сколько записей журнала будет удалено.

Если геометрию стереть не удалось, материал НЕ удаляется: иначе в чертеже
остались бы линии на слое, которому больше не соответствует ни одна позиция
реестра, и восстановить связь было бы нечем.

Замеры этого материала в **других** чертежах убираются из журнала, но их
полилинии остаются — плагин правит только открытый чертёж. Диалог называет
такие чертежи поимённо.

После удаления имя слоя освобождается, пустой слой вычищается из чертежа,
а если удалённый материал был выбран инструментом — выбор снимается.

## Слои

Имя слоя = основа материала + участок:

| Материал | Участок | Слой |
|---|---|---|
| Труба ⌀89x4 | — | `PIPE_D89x4` |
| Труба ⌀89x4 | Этаж 1 | `PIPE_D89x4_Этаж 1` |
| Воздуховод 1250x800, 0,9 мм | Кровля | `DUCT_1250x800_t0.9_Кровля` |
| Воздуховод круглый ⌀200, 0,7 мм | — | `DUCT_D200_t0.7` |
| Кабель 5х2,5 | Этаж 1 | `CABLE_5x2.5_Этаж 1` |
| Фильтр Dn15 | — | `PIECE_Dn15` |

**Участок входит в имя слоя намеренно.** Журнал ведётся автоматически, и
определить участок плагин может только по слою — иначе полилинии двух участков
лежали бы вперемешку на одном слое и разделить их было бы нечем. Побочный
плюс: удаление записи теперь стирает геометрию только своего участка.

Имя слоя разбирается обратно в пару «материал + участок»
(`LayerNameFactory.TryResolveLayer`). При совпадении основ у двух разных
материалов второму добавляется `#2` — не `_2`, потому что подчёркивание
занято под участок.

Слой находится или создаётся и становится текущим сразу при выборе материала —
рисовать можно без дополнительных действий. Палитра показывает состояние слоя:
«активный», «создан, но не текущий» или «будет создан при замере».

Имя слоя строится для **любого** материала. Если характеристик нет или после
чистки запрещённых символов от кода ничего не осталось, включается запасной
шаблон `PIPE_N<хеш>` / `MEAS_N<хеш>` — хеш считается от наименования, поэтому
у одного материала имя постоянно, а у разных различается. Если валидное имя
собрать не удалось вовсе, плагин показывает ошибку с указанием позиции реестра,
а не пишет замеры «куда-нибудь».

Цвет детерминирован: трубы — ACI 1…128, воздуховоды — 129…255 (индекс 7
пропускается, он сливается с фоном). Вес линии — `LineWeight200` (2,00 мм),
см. раздел «Отступления от ТЗ». Имя слоя сохраняется в каждой записи журнала.

## Порядок работы

1. «Выбрать материал» — окно с поиском по наименованию и вкладками по классам.
   Инструмент замера определяется классом материала, переключать его не нужно.
   Слой материала сразу становится текущим.
2. Заполнить «Участок» (можно менять в любой момент) — он входит в имя слоя.
3. «Начать замер» — запускается рисование полилиний одна за другой.
   Enter или Esc на запросе первой точки — выход.
4. «Подъём» / «Опуск» — ввод длины вертикального участка в мм. Суммы копятся
   по ключу «слой + участок» и не зависят от геометрии.
5. Журнал обновляется сам. После рисования, стирания и правки чертежа длины
   пересчитываются по слоям: одна строка на сочетание «материал + участок +
   DWG». Кнопки «Записать» нет — см. «Автообновление журнала».
6. «Экспорт в Excel» — файл `<имя DWG>_замеры.xlsx` рядом с чертежом;
   при повторном экспорте добавляется индекс (`_2`, `_3`, …), существующие
   файлы не перезаписываются.

### Округление длин

Единое правило: `Math.Round(value, 2, MidpointRounding.AwayFromZero)` —
до 0,01 м, в `MeasurementRounding`. Применяется к **итогу**: сумма полилиний
слоя плюс вертикальные участки. Слагаемые (`HorizontalLengthM`,
`VerticalLengthM`) хранятся с полной точностью — иначе на сотне отрезков
ошибка округления накапливается и итог в ведомости перестаёт сходиться
с суммой по чертежу.

`AwayFromZero`, а не банковское округление по умолчанию: в спецификации
12,345 должно давать 12,35, а не 12,34.

### Подписи на чертеже

Каждый замерный объект подписывается сразу при создании, текстом ISOCPEUR
на том же слое и того же цвета, что и сам объект.

| Объект | Подпись | Высота | Положение |
|---|---|---|---|
| Полилиния | собственная длина в метрах | 250 | середина по длине, параллельно линии, поднята на 125 по нормали |
| Круг-маркер ⌀70 | порядковый номер | 25 | точно в центре круга |

Флажок **«Показывать длину участков»** в палитре управляет подписью длины для
**новых** полилиний. По умолчанию включён, значение сохраняется между сеансами
в `%APPDATA%\PTOMeasurePro\settings.json`. На уже созданные подписи
переключение не влияет — они остаются на месте.

Текстовые стили создаются одним сервисом (`TextStyleService`): подписи
используют `ISOCPEUR`, таблица ведомости — `ISOPEUR_1` (та же гарнитура).
Если стиль с таким именем уже есть в чертеже, он берётся как есть —
пользовательские настройки стиля не перезаписываются. Стиль назначается
ячейкам таблицы, а не общему `TableStyle`: тот может быть общим для других
таблиц чертежа.

Подпись длины ставится в точке **половины длины**, а не в центре габаритов:
у изогнутой трассы это разные места, и центр габаритов может вообще не лежать
на линии. Поднимается подпись по нормали к линии, а не строго вверх по Y —
иначе у вертикальной трассы текст лёг бы прямо на неё. Текст разворачивается
на 180°, если трасса идёт справа налево, чтобы не читаться вверх ногами.

Высота номера 25 подобрана под трёхзначное число в круге ⌀70: в ISOCPEUR
цифра занимает около 0,55 высоты по ширине, значит «999» — это ~41x25 мм,
половина диагонали ≈ 24 мм против радиуса 35 мм.

**Нумерация штучек сквозная в пределах слоя**, а слой — это «материал +
участок». То есть у каждого материала на каждом участке своя нумерация
с единицы, и номер на чертеже соотносится со строкой журнала. Следующий номер
берётся как максимум существующих плюс один: после удаления маркера
из середины номера не съезжают и не начинают повторяться.

Подписи не считаются замерами — сканирование смотрит только на полилинии
и круги. Но при очистке слоя (удаление материала) они стираются вместе
с геометрией, иначе остались бы висеть в пустоте.

### Штучные изделия

Каждое изделие помечается **кругом ⌀70** на слое материала: кнопка становится
«Начать подсчет», пользователь указывает только центр — круг ставит плагин.
Количество = число таких кругов на слое.

Диаметр фиксирован (`PluginSettings.PieceMarkerDiameterMm`, допуск 0,5 мм)
именно потому, что по нему сканирование отличает маркеры от прочей графики
слоя. Кнопки «Подъём», «Опуск» и «Сбросить вертикальные» для штучных изделий
отключаются: длины у них нет.

### Удаление и очистка

Отдельной кнопки удаления записи нет: журнал выводится из чертежа, поэтому
запись убирается сама, как только опустеет её слой. Чтобы убрать замер —
сотри его геометрию в AutoCAD обычным способом.

**«Очистить журнал»** сбрасывает только записи текущей сессии. Чертёж не
меняется: полилинии, круги, подписи, слои, реестр материалов и выгруженные
файлы Excel остаются на месте. Автоведение при этом не отключается, поэтому по
существующей геометрии записи соберутся заново при ближайшем пересчёте — об
этом сказано прямо в подтверждении, иначе кнопка выглядела бы сломанной.
Ручные правки очистка теряет, и диалог называет их количество.

Удалить материал целиком (вместе с геометрией и записями по всем чертежам)
можно кнопкой «Удалить материал» в окне выбора: слой на время очистки
разблокируется и размораживается, потом состояние возвращается — на
заблокированном слое AutoCAD не отдаёт объект на запись, и удаление молча
провалилось бы.

### Правка журнала в таблице

Колонки идут в порядке: **Наименование материала**, **Ед. изм.**, **Кол-во**,
далее Участок, Слой, Файл DWG. «Тип» и «Характеристика» не выводятся — всё
это уже есть в наименовании.

«Кол-во» — одна колонка на оба класса: у Pipe/Duct/Cable это длина в метрах
и «м», у Piece — число изделий и «шт». Раздельные «Длина» и «Количество»
всегда наполовину пустовали.

Редактируются три колонки: **Наименование материала** (список реестра),
**Кол-во** и **Участок**. Ед. изм., слой, файл DWG и класс материала
не редактируются — они вычисляются.

Двойной клик по строке делает её материал текущим: подбирается инструмент по
классу, активируется слой, поле «Участок» заполняется из строки. Событие не
помечается обработанным, поэтому редактирование ячейки по двойному клику
продолжает работать.

**Смена материала или участка — это перенос геометрии на другой слой.** Слой
кодирует пару «материал + участок», поэтому правка переносит полилинии, круги
и подписи на новый слой (`MoveMeasurementGeometry`), переносит вертикальные
участки и перепривязывает запись к новому ключу. Геометрия при этом не
удаляется и не перерисовывается — меняется только принадлежность слою.
Опустевший старый слой убирается.

Отклоняется с сообщением:

| Ситуация | Почему |
|---|---|
| материала нет в реестре | нечего записать в `MaterialName` |
| замена линейного материала штучным (и наоборот) | на слое лежат полилинии либо круги — запись осталась бы без своей геометрии |
| дубликат «материал + участок + DWG» | две одинаковые строки журнала недопустимы |
| запись из другого чертежа | плагин не двигает геометрию в неоткрытом DWG |

**Длина и количество, введённые вручную, переживают пересчёт.** Они хранятся
отдельно от измеренных (`ManualLengthM` / `ManualQuantity`), и сканирование
обновляет только измеренную часть. Иначе правка жила бы 250 мс до ближайшего
скана. Такая строка подсвечивается, а пустая ячейка снимает ручное значение
и возвращает измеренное.

Пока открыт редактор ячейки, автопересчёт приостановлен: он пересоздаёт
строки коллекции, и правка потерялась бы прямо под руками.

### Ведомость: таблица в чертеже и Excel

Состав и порядок строк заданы в одном месте — `StatementBuilder` в домене.
И таблица AutoCAD, и выгрузка в Excel берут строки оттуда, поэтому два
представления одной ведомости не могут разойтись.

**Столбцы:** п/п | Наименование материала | Ед. изм. | Кол-во.
Единица берётся по классу («м» для Pipe/Duct/Cable, «шт» для Piece), а не из
реестра, где встречаются «м.п.» и «шт.». Ни итогов, ни площадей, ни участка,
ни слоя, ни файла DWG.

**Группировка:** «наименование + единица + участок» в пределах текущего DWG.
Участок в ведомость не выводится, но входит в ключ — значит один материал,
замеренный на двух участках, даёт две строки с одинаковым наименованием.

**Порядок:** трубы → воздуховоды → кабели → штучные изделия; внутри группы —
по наименованию, при совпадении — по участку.

Кнопка «Вставить таблицу замеров» (команда `CMPTABLE`) запрашивает точку и
создаёт **одну** таблицу с заголовком «Ведомость смонтированного оборудования
и материалов» в текущем пространстве — модели или листе.

Таблица — производное отображение журнала: своего скана чертежа она не делает,
обновление вызывается там же, где обновляется журнал, и просто перечитывает
готовые строки. Тот же debounce, никакой дополнительной работы по ModelSpace.

Ссылка на таблицу хранится в словаре именованных объектов чертежа под ключом
`PTO_MEASURE_PRO_TABLE_ID` в виде Xrecord с мягким указателем — так она
переживает сохранение и переоткрытие DWG. Перед каждым обновлением ссылка
проверяется: существует ли объект, не стёрт ли он и действительно ли это
`Table`. Битая ссылка вычищается из словаря, и обновление ничего не делает —
удалить таблицу руками безопасно. Дублей не бывает: если таблица уже есть,
команда спрашивает — перенести её в указанную точку или создать заново.

Таблица кладётся на отдельный слой `PTO_TABLES`, чтобы не попадать под очистку
замерных слоёв и не участвовать в подсчётах.

**Excel** формирует один лист «Ведомость» с тем же составом: заголовок,
объединённый по A:D, шапка, строки. Количество пишется числом, чтобы с
ведомостью можно было продолжить работать. Файл по-прежнему кладётся рядом
с DWG с индексом при повторном экспорте.
### Автообновление журнала

Журнал пересобирается сам — отдельной кнопки пересчёта нет. Плагин слушает
завершение любой команды AutoCAD (`CommandEnded` / `Cancelled` / `Failed`):
через команды проходит всё, что нас интересует — рисование, стирание,
СВОЙСТВА со сменой слоя, ОТМЕНИТЬ. Слушать `ObjectErased` на базе было бы
в разы дороже: событие приходит на каждый объект.

Пересчёт запускается не в самом обработчике, а по таймеру через 250 мс:
команда в момент события ещё сворачивается, и работа с базой оттуда
ненадёжна. Тот же таймер склеивает пачку событий (серию ПЛИНИЙ) в один
пересчёт.

Все слои обмеряются **за один проход** по пространству модели
(`AcadWorkspace.ScanLayers`), а не по одному обходу на запись — иначе при
30 записях каждая команда стоила бы 30 полных обходов чертежа.

Пересчёт срабатывает после изменений чертежа, журнала, реестра материалов
и ввода вертикальных участков, а также принудительно перед экспортом.

**Опустевший слой** — запись автоматически удаляется из журнала.

Исключение: запись, у которой полилиний нет, но заданы вертикальные участки,
сохраняется. Подъёмы и опуски вводятся с клавиатуры и на чертеже не рисуются —
стояк, замеренный только по высоте, это законный замер, и автоудаление молча
стёрло бы данные, которые нечем восстановить. Если нужно жёсткое правило
«нет полилиний — нет записи», поставь `PluginSettings.DeleteRecordsWithOnlyVerticalRuns = true`.

### Если полилинии переносили на другой слой

Старая строка обнулится сама при ближайшем пересчёте, а на новом слое запись
появится сама при первом же пересчёте — журнал выводится из чертежа.

## Отступления от ТЗ

Два места, где ТЗ противоречило само себе или было неполным:

1. **Толщина замерных линий.** В ТЗ указано «1,8 мм», но в примере —
   `LineWeight018`, то есть 0,18 мм. В шкале AutoCAD значения 1,8 мм нет:
   ближайшие 1,58 и 2,00 мм. Взято `LineWeight200` (2,00 мм).
   Меняется одной константой — `PluginSettings.MeasureLineWeight`.

2. **Имя слоя воздуховода.** В ТЗ пример `DUCT_1250x800`, но воздуховоды
   одного сечения из стали разной толщины — разные позиции спецификации,
   и их замеры сложились бы в один слой. В код добавлена толщина листа:
   `DUCT_1250x800_t1`. Плюс общий механизм: если два разных материала всё же
   дают одинаковый код, второму добавляется `#2` — подчёркивание занято
   под участок (см. «Слои»).

Дополнительно к списку кнопок из ТЗ добавлены «Сбросить вертикальные участки»
(исправление ошибочного ввода подъёма/опуска) и «Обновить реестр материалов».

## Важные допущения

- **Единицы чертежа — миллиметры** (`PluginSettings.DrawingUnitsPerMeter = 1000`).
  Для чертежей в метрах поставить 1.
- **Журнал живёт в памяти сессии** и не сохраняется между запусками AutoCAD.
  Экспорт в Excel — способ зафиксировать результат.
- Замеры считаются в **пространстве модели**.
